What it does

A generator that checks the site it builds

Each card opens its section on the features page.

A quality gate on every build

Every build scores the site on ten pillars and reports each issue it finds, page by page.

What the gate checks

Fifteen audit gates

ssg audit checks the built files: WCAG, structured data, CSP and SRI, links, metadata, feeds, images and more.

See the gates

CSP and Subresource Integrity

Inline styles and scripts move to hashed files, and every local stylesheet and script carries an integrity hash.

How pages are hardened

Content schemas

Declare the front matter each page must carry, and the build stops with a named error when a field is missing.

How schemas work

Feeds, sitemaps and search

RSS, Atom and JSON feeds, sitemaps, a search index and llms.txt come out of the same build.

What a build writes

One-command deploys

ssg deploy builds and ships to Netlify, Vercel, Cloudflare Pages, GitHub Pages or S3.

Deploy targets

Commands

Build, check, audit

Three of the six subcommands in ssg 0.0.69.

ssg build

Build the site

Compiles Markdown content with templates into the output directory and runs the quality gate.

All subcommands

ssg check

Validate without writing

Runs the content, accessibility, SEO, JSON-LD and CSP checks and writes no output.

All subcommands

ssg audit

Audit the result

Runs the fifteen gates against the built files and exits non-zero on an error.

The fifteen gates

Install

From nothing to a built site

Install the crate, scaffold a project, build it and audit the output. Building from source needs Rust 1.89 or newer; release archives need nothing.

  • cargo install ssg
  • GitHub release archives
Read the getting started guide
Security

Releases you can verify

Every release package comes with a SHA-256 sum, an OpenPGP signature and a build provenance attestation.

The signing key is in KEYS.asc in the repository. The security page shows how to check an archive before you run it, and how to report a vulnerability.

What it does

A generator that checks the site it builds

Each card opens its section on the features page.

A quality gate on every build

Every build scores the site on ten pillars and reports each issue it finds, page by page.

What the gate checks

Fifteen audit gates

ssg audit checks the built files: WCAG, structured data, CSP and SRI, links, metadata, feeds, images and more.

See the gates

CSP and Subresource Integrity

Inline styles and scripts move to hashed files, and every local stylesheet and script carries an integrity hash.

How pages are hardened

Content schemas

Declare the front matter each page must carry, and the build stops with a named error when a field is missing.

How schemas work

Feeds, sitemaps and search

RSS, Atom and JSON feeds, sitemaps, a search index and llms.txt come out of the same build.

Security

Releases you can verify

Every release package comes with a SHA-256 sum, an OpenPGP signature and a build provenance attestation.

The signing key is in KEYS.asc in the repository. Release packages are built for Linux and macOS on x86_64 and arm64 and for Windows on x86_64: .tar.gz archives, a .zip and an .msi, .deb and .rpm packages and a macOS .pkg. The crate is on crates.io. The security page shows how to check an archive before you run it, and how to report a vulnerability.
